# Termennetwerk MCP server: design + implementation plan

## Context

The goal is a **public, hosted MCP server** on top of the NDE Network of Terms (Termennetwerk), so anyone
(heritage institutions, researchers, Claude.ai / Claude Desktop users via "Add custom connector") can let an
AI search Dutch heritage terminology sources, resolve term URIs and reconcile names to term URIs. No
client library or MCP server for the Network of Terms exists yet.

Upstream (verified live on 2026-11-17, no auth needed):
- GraphQL `https://termennetwerk-api.netwerkdigitaalerfgoed.nl/graphql`: `sources(genres)`,
  `terms(sources!, query!, genres, queryMode=OPTIMIZED, languages, limit=100, timeoutMs=10000)`,
  `lookup(uris! (max 1000), languages, timeoutMs)`. 58 sources. Results are unions
  (`Terms | TranslatedTerms | Error`, `Source | Error`, `Term | TranslatedTerm | Error`); passing
  `languages` switches labels from `[String]` to `[{language,value}]`. Timeout max 60 s.
- Reconciliation (W3C v0.2): `GET/POST /reconcile/{sourceUri}` (manifest / queries), `POST /extend`,
  `GET /extend/propose`. Person matching via properties (birthDates, deathDates, birthPlaces, parents, ...).
  Accept-Language `nl|en` drives catalog metadata and reconciliation output. Wikidata sources have no
  reconciliation feature.
- Upstream source: a local checkout of [network-of-terms](https://github.com/netwerk-digitaal-erfgoed/network-of-terms) (schema in `packages/graphql/src/schema.ts`,
  reconciliation routes in `packages/reconciliation/src/server.ts`).

## Decisions (made by the maintainer)

- Audience: public hosted server (not local stdio).
- Tools: list sources, search terms, look up URIs, reconciliation (incl. data extension).
- Approach A: own TypeScript server modelled on the Open Archives MCP server ([coret/openarchieven-mcp-server](https://github.com/coret/openarchieven-mcp-server)) (Express + MCP SDK
  StreamableHTTP + zod). Rejected: Apollo MCP Server (no reconciliation, raw GraphQL output), Python FastMCP
  (diverges from the maintainer's other MCP servers).
- Hostname `mcp-termennetwerk.coret.org`.
- GraphQL client: `graphql-request` + `@graphql-codegen` (typed documents).
- Cache: Redis, like OA (degraded mode without Redis).
- Incoming rate limit per IP with `express-rate-limit` (60 tool calls/min/IP, `trust proxy` 1 behind
  Apache, 429 with a clear JSON-RPC error message). Outgoing limiter copied from OA.
- `search_terms`: max 10 sources per call (`MAX_SOURCES = 10`).
- Logging (pino): tool name, number of sources/URIs/queries, duration, cache hit, error class. No query
  text, URIs or IPs in the app log.
- NDE is not informed beforehand (open API, no terms).

## Tools

All tools are read-only (`readOnlyHint: true`, `openWorldHint: true`), return compact JSON as text plus
`structuredContent` with an output schema. Source arguments accept a source URI **or** its exact
name/alternateName (resolved against the cached source list; unknown names yield an error listing close
matches), because LLMs reliably know names, not URIs.

| Tool | Upstream | Arguments | Output (flattened) |
|---|---|---|---|
| `list_sources` | GraphQL `sources` | `genres?`, `language? (nl\|en)` | uri, name, alternateName, description, inLanguage, genres[name], creators[name], reconciliation url, supportsGenreFilter, available, lastChecked |
| `search_terms` | GraphQL `terms` | `sources[]` (1..MAX_SOURCES), `query`, `languages? (nl\|en\|fy)`, `genres?`, `limit? (default 20, ≤100)`, `timeoutMs? (≤60000)`, `queryMode?` | per source: `{source, ok, error?, responseTimeMs, total, terms[]}`; term = uri, prefLabel, altLabel, definition, scopeNote, broader/narrower/related/exactMatch as `{uri,label}`, seeAlso, place `{name, latitude, longitude, addressCountry}`, person summary (dates/places, only when present). Empty fields dropped. |
| `lookup_terms` | GraphQL `lookup` | `uris[]` (≤200, my cap for token size), `languages?`, `timeoutMs?` | per uri: `{uri, source?, ok, error?, term?}` |
| `reconcile` | `POST {features[].url}` | `source`, `queries[]` (≤10) of `{query, type?, limit?, properties?: [{pid, v}]}`, `language? (nl\|en)` | per query: candidates `{id, name, score, match, type[], description, features?}` |
| `extend_terms` | `POST /extend` | `ids[]` (≤100), `properties[]` (enum of the 26 ids from `/extend/propose`), `language?` | per id: property → values (`str` or `{id,name}`); ids missing from upstream `rows` reported as `notFound` |

Translated labels (when `languages` is given) are flattened to `{ "nl": [...], "en": [...] }` per label
field. Tool descriptions explain: search ≠ lookup, pick sources first via `list_sources`, 4 of 58 sources
(Wikidata) have no reconciliation, upstream may answer per-source errors while other sources succeed,
`fy`-only gives empty labels.

### Upstream facts from the builder check (live API, 2026-11-17)

The live API is **ahead of** the local checkout a local checkout of [network-of-terms](https://github.com/netwerk-digitaal-erfgoed/network-of-terms) (that checkout lacks
reconciliation property matching and has only 12 extension properties): build and record fixtures
against the live API only.
- `Language` enum live: `en | fy | nl`. Reconcile/extend take only `nl|en` (Accept-Language).
- `terms.limit` is applied **inside the SPARQL query before ranking** (verified: RKD "Rembrandt" limit 3
  misses `artists/66219`). So: never pass a small `limit` upstream; request upstream default (100), then
  rank exact/prefix prefLabel matches first and cut to the tool's `limit`, reporting `total`.
- `timeoutMs` > 60000 is a GraphQL error: cap in zod. Handle partial `errors` + `data` responses.
- Reconcile batch is an object keyed by query id (`{"q0":{...}}`); properties are `[{pid, v}]`;
  matchable pids from `GET /suggest/property`: givenNames, familyNames, birthDates, deathDates,
  birthPlaces, deathPlaces, genders, occupations, nationalities, parents, children, spouses, siblings
  (put these in the tool's zod enum). Candidates have no `match` field: derive `match` ourselves
  (score 100 / single top candidate). With `Accept-Language: en` RKD names can be `""`: fall back to an
  `nl` request or to `description`.
- Reconcile URL: use the source's `features[type=RECONCILIATION].url` as-is (watch `#`/`?` in source URIs:
  encode the fragment correctly).
- Upstream runs reconcile queries sequentially (up to 10 s each): cap queries at 10 and set the Apache
  `ProxyTimeout` to 180 s.
- Lookup cap upstream is 1000 (`MAX_LOOKUP_URIS`); unknown URI gives `SourceNotFoundError`/`NotFoundError`.
- Response size: 100 RKD "Jan" terms ≈ 31 KB without person data. Byte budget per tool response
  (≈ 60 KB) with an explicit truncation note.
- Cache: normalise keys (sorted sources/languages); never cache a response containing any per-source error.
- Copy OA's `validateOrigin` (DNS-rebinding protection) and outgoing `RateLimiter`.

## Implementation steps (one branch, named commits)

1. `git init`, scaffold package (deps: `@modelcontextprotocol/sdk`, `express`, `express-rate-limit`, `zod`,
   `graphql`, `graphql-request`, `ioredis`, `pino`; dev: `@graphql-codegen/cli` + `client-preset`/`typescript-operations`,
   `typescript`, `tsx`, `@types/*`). Commit the design doc first.
2. Upstream layer: operations, codegen against live endpoint, `reconcile.ts`; record fixtures.
3. `flatten.ts` + `sources.ts` with unit tests on fixtures (incl. error union, TranslatedTerms, unknown URI
   in lookup, name resolution).
4. `cache.ts` (Redis, TTLs, degraded mode).
5. Tools + `mcp.ts`; `server.ts` with routes, health, well-known, landing page.
6. README (English, conformance-report style, Claude connector instructions, what does NOT work yet),
   `server.json`, server card.
7. Deploy: `start.sh` under a process supervisor; Apache vhost `mcp-termennetwerk.coret.org` as a reverse proxy
   to port 3004 with the existing wildcard certificate; configtest and reload.
8. Ask the maintainer before: creating the GitHub repo / pushing, publishing to the MCP registry.

## Verification

- `npm test` (unit tests on fixtures), `npm run build`, `tsc --noEmit`.
- Live smoke: `npx @modelcontextprotocol/inspector` against `http://localhost:3004/mcp`; call each tool:
  list_sources; search_terms CHT "fiets"; search_terms with `languages:["nl","en"]` on AAT;
  lookup_terms on a CHT URI + an unknown URI; reconcile RKDartists "Rembrandt" (expect score 100,
  `https://data.rkd.nl/artists/66219`) and a person query with `birthDates`; extend_terms prefLabels+broaderTerms.
- Rate limit: 61st call within a minute from one IP gets 429; search_terms with 11 sources is rejected by zod.
- search_terms RKD "Rembrandt" `limit: 3` contains `artists/66219` (proves upstream-limit workaround + re-rank).
- Redis: second identical call is served from cache (log line), `redis-cli -n 9 keys 'tn:*'`; stop Redis →
  `/health` shows degraded, tools still work.
- Public: `curl https://mcp-termennetwerk.coret.org/health`, add as custom connector in claude.ai and
  run one search end-to-end.
